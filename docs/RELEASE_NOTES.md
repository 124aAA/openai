# QingNode 0.2.2 — 系统版本字段冲突修复

- 修复 Ubuntu / Debian 的 `/etc/os-release` 中 `VERSION` 覆盖安装器发行 tag，导致第 3 步提示“仓库名或正式版本号无效”。系统信息在子进程中读取，只传回系统标识和系统版本号。
- 保留默认发行版本和用户显式传入的 `--version`，仓库名与发行版本错误分别报告；拒绝 `.` / `..` 仓库路径片段。
- 安装器测试补齐 `VERSION` / `PRETTY_NAME` 字段，新增五种系统标识的在线首装和重装、真实宿主系统信息、指定版本与非法参数回归。

以 root 重新下载安装器可修复旧版本辅助脚本，同时保留已有节点参数：

```bash
bash <(wget -qO- https://raw.githubusercontent.com/124aAA/openai/v0.2.2/install.sh) --reinstall
```

原 v0.2.1 的 `self-update` 会调用旧辅助脚本，仍可能触发同一错误；这次升级应使用上面的修复入口。核心仍为官方 sing-box 1.14.0，节点数据库格式不变。该版本保留真实核心 TCP/UDP 发布门槛，真实 VPS 全流程和公网客户端仍需验收。

## 0.2.1 功能回顾

发行仓库：124aAA/openai。新增无需参数的在线安装入口，自动选择架构并核验包内外 SHA-256；已安装时直接打开菜单，保留节点参数。独立 install.sh、Bash 进程替换和本地发行包均可使用，残缺本地包不会切换下载源。管理器更新可使用 `self-update --version v0.2.1`。

0.2.1 延续以下 0.2.0 功能和数据格式：

基于 0.1.0 增量改造，保留 Bash + Go + sing-box + systemd。

- P0：分离运行与自启，校验实际监听所属进程，完善只读诊断、安装/卸载容错和配置回滚；重复执行保留身份，支持修复损坏的派生配置。
- P1：分级中文菜单、CLI 别名、多节点/凭据维护、随机端口、独立 REALITY 参数轮换、完整信息和导出；v2 加密快照及恢复前备份；核心/管理器更新分离；已启用 UFW 项目规则管理、系统 BBR。
- P2：加入 SS2022，提取编译期协议适配器，保留既有 HY2，增加故障注入和显式空白 VPS 验收入口。TUIC 和完整英文尚未实现。

兼容 0.1.0 数据及 v1 加密备份；旧节点不会自动换 UUID、密钥、short ID、密码或端口。0.2.0 新字段不能直接交给 0.1.0 管理器读取。

本地业务回归、ShellCheck、安装器模拟、官方 sing-box/Mihomo 配置解析均经过实际执行。开发容器内真实核心 TCP/UDP 测试因环境禁止路由订阅而失败；GitHub 发布流程保留真实核心流量测试，全部通过才上传发行包。真实 systemd、五种系统安装、云防火墙、BBR、ACME、移动端及 ARM64 执行未验证。

完整范围和实测结果见 TEST_REPORT.md。快照不包含 ACME 缓存；卸载前自动快照为权限 600 的明文文件。全量卸载保留专用账户及用户启用过的 BBR 设置。
