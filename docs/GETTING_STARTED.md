# 新手指南：从安装到导入客户端

按这份指南，你可以在自己的 VPS 上创建一个节点，把连接配置导入自己的客户端，并区分“服务器已启动”与“实际连接已通过”。出现错误时，转到 [故障 FAQ](FAQ.md)；完整参数见 [README](../README.md#常用命令速查)。

> 本文对应本次本地源码。文中标明的“本次菜单改进”尚未随本次工作发布：选节点/凭据时 `0` 返回、无效序号重试、向导 `:cancel` 取消、按用途选择导出。公开安装入口仍下载已发布的发行包；不要仅凭版本号或这份文档认定服务器已包含这些改动，以实际提示为准。

## 1. 先确认 VPS 和客户端条件

QingNode 管理自己的 `qingnode.service` 和 sing-box 核心。请在 VPS 的 SSH 终端操作；SSH 是你远程登录服务器的终端。一般用 root 登录，普通 sudo 用户先运行 `sudo -i`。

当前安装器识别 Debian 12/13、Ubuntu 22.04/24.04/26.04，要求 systemd 管理服务、amd64 或 arm64 CPU，并能访问 GitHub 和 apt 软件源。这是系统识别范围，各平台的实机验收情况仍以 [测试报告](TEST_REPORT.md)为准。

服务器需要一个客户端能连接的公网 IP 或域名，以及未被其他程序占用的端口。还要在 VPS 服务商的控制台核对云安全组/网络防火墙：它们控制到达服务器之前的流量，QingNode 无法在服务器内替你确认全部规则。

| 协议 | 本次意味着什么 | 必要条件 | 需要放行的节点流量 |
| --- | --- | --- | --- |
| REALITY | VLESS + REALITY + XTLS Vision，用外部 TLS 握手目标配合连接 | 客户端支持这一组合；VPS 能访问符合要求的目标；不需要给 VPS 申请自己的 TLS 证书 | 所选端口 TCP |
| SS2022 | Shadowsocks 2022，当前加密方式为 `2022-blake3-aes-256-gcm` | 客户端支持该加密方式及“服务密钥:用户密钥”的多用户密码格式；不需要 TLS 证书 | 所选端口 TCP 和 UDP |
| Hysteria2 | 使用 UDP 传输、通过 TLS 验证服务器身份 | 客户端支持 Hysteria2；可验证的证书与匹配的名称；UDP 网络可达 | 所选端口 UDP；ACME 签发另需 TCP 80 |

不确定选哪个时，先核对你准备使用的客户端。REALITY 的默认流程省去自有域名和证书准备；Hysteria2 需要先准备证书条件；SS2022 需要明确客户端的加密方式支持。三个协议都能导出配置，导出成功不代表任何版本的客户端都一定能导入。

Android 上使用 v2rayNG、NekoBox 等应用时，核对应用版本和内置核心的协议支持。使用 Mihomo 系客户端时，核对实际内核版本及本地 YAML 导入方式。使用 sing-box 客户端时，导出的完整 JSON 按本项目 sing-box 1.14 配置生成；其他版本应核对字段兼容。移动端导入和实际网络连接仍需你在设备上测试。

## 2. 执行安装并选择协议

在 VPS 终端运行与 README 相同的安装入口：

```bash
bash -c 'set -e; f=$(mktemp); trap "rm -f \"$f\"" EXIT; curl -fsSL --retry 3 https://raw.githubusercontent.com/124aAA/openai/main/install.sh -o "$f"; bash "$f"'
```

先出现协议选择，再开始安装。输入 `1` 选择 REALITY、`2` 选择 SS2022、`3` 选择 Hysteria2；首屏输入 `0` 退出。不要把文档里的示例地址或域名当成自己的服务器参数。

首次安装选 REALITY 或 SS2022 时，会自动探测公网地址、选择可用端口并生成凭据。REALITY 会筛选握手目标。这些默认值能减少输入，但仍需核对成功信息中的连接地址、端口及协议，尤其是 NAT VPS。

安装 Hysteria2 或在已安装菜单中选择 `6 搭建新节点` 时，按提示填写：

| 输入项 | 怎么填 |
| --- | --- |
| 节点名称 | 自己容易辨认的名称，如地区与用途；名称可以修改，节点 ID 保持稳定 |
| 服务器地址 | 客户端实际连接的公网 IP 或域名；自动探测结果只作默认值，需按自己的网络确认 |
| 端口 | 提示允许时回车使用 `auto`；固定端口须确认未被占用且服务商允许入站 |
| REALITY 目标域名 | 提示允许时使用 `auto`；它是握手目标，不是 VPS 公网地址；不能随便填一个不存在的域名 |
| Hysteria2 证书域名 | 证书能够验证的名称，客户端将按这个名称校验 TLS |
| 凭据 | 首次创建自动生成；无需自己拼 UUID、密码或密钥 |

本次菜单改进中，创建向导的输入提示允许 `:cancel` 返回，未提交节点前不会落盘节点或凭据。它取消的是当前创建操作；如果外层安装器已经下载管理器、安装依赖或准备目录，这些准备动作不会因此全部撤销。看到“已取消”后，可以回到菜单重新创建。外层首次协议选择仍按其 `0` 提示退出。

无交互终端的自动化部署请用 README 中的显式 `--auto` 或完整参数，不要把菜单输入当自动化接口。

## 3. Hysteria2 的证书方式怎么选

**`acme` 自动签发**：让 sing-box 的证书组件申请和续期。证书域名的 DNS 必须指向本机，从公网能访问本机 TCP 80，且本机 TCP 80 未被其他服务占用。节点本身另外使用所选 UDP 端口。若已经有网站占用 TCP 80，先使用已有 PEM 证书或自行规划签发方式，QingNode 不会停止现有网站。

ACME 指“自动申请证书”，不代表输入域名后一定申请成功。签发可能受 DNS、端口、CA 限额和等待时间影响；证书组件已配置也不等于证书已经签发。当前真实签发/续期仍有未验证项，见测试报告。

**`pem` 导入已有证书**：准备可信的完整证书链和匹配私钥，输入服务器上的文件路径。证书名称须与填写的证书域名匹配，证书须在有效期内。QingNode 会复制导入内容；原文件续期以后，需要再次用菜单的导入证书入口或 `edit --cert ... --key ...` 导入。

不要把“跳过证书校验”作为默认处理。使用自签名或私有 CA 的证书时，各客户端的信任/指纹配置可能不同；本项目不会自动导出所有客户端的信任设置，应先明确自己的证书链如何被设备信任。

## 4. 取得客户端配置

安装成功后，记录自己的节点名称/ID、服务器地址和端口。完整链接是连接凭据，请只在自己的终端和设备间复制。

之后运行 `sudo qingnode`，主菜单选择 `2 链接与导出`。本次菜单改进允许按数字选择用途，回车默认分享 URI，也兼容 `uri`、`qr`、`mihomo`、`provider`、`sing-box`、`base64` 这些原格式文字；输入 `0` 返回。多个凭据时选择准备给这台设备使用的一个；独立设备凭据方便以后单独撤销或轮换，已有一个凭据也可以继续使用。选节点或凭据的无效序号会重新询问当前步骤。

| 想完成的事 | 导出方式 | 客户端里怎么做 |
| --- | --- | --- |
| 手机扫描或快速复制 | `qr` 二维码或 `uri` 分享链接 | 扫描二维码，或复制完整链接后用“从剪贴板导入”等入口 |
| 使用 Mihomo 系客户端 | `mihomo` 完整 YAML | 安全下载到设备，再从本地配置入口导入 |
| 使用 sing-box 客户端 | `sing-box` 完整 JSON | 安全下载到设备，再从本地配置入口导入 |
| 把节点加入已有 Mihomo 配置 | `provider` 片段 | 在已有配置中引用或合并；它不是完整可运行配置 |
| 获取 Base64 文本 | `base64` | 按客户端实际支持方式使用；它不是在线订阅网址 |

二维码显示错位时，放大终端或改为复制 URI。文件路径 `/root/client.json` 是 VPS 上的本地文件位置，不能直接粘贴到客户端的“订阅网址”栏。客户端 JSON/YAML 只提供本机代理入口与单节点转发，不自动接管设备的系统代理、TUN 或复杂分流；导入后还要按客户端要求启用实际流量入口。

也可以用 CLI。先查自己的节点及凭据 ID，然后替换下方的 `NODE_ID` 与 `USER_ID`：

```bash
sudo qingnode list
sudo qingnode info --id NODE_ID
sudo qingnode export --id NODE_ID --user USER_ID --format uri
sudo qingnode export --id NODE_ID --user USER_ID --format qr
sudo qingnode export --id NODE_ID --user USER_ID --format sing-box --out /root/client.json
sudo qingnode export --id NODE_ID --user USER_ID --format mihomo --out /root/client.yaml
```

`NODE_ID`、`USER_ID` 是占位文字，不要原样执行。只有一个凭据时可省略 `--user`；多个凭据应显式选择。导出文件权限为 600，即仅文件拥有者可读写，并拒绝覆盖已有文件；文件已存在时换新文件名，避免误覆盖自己的配置。

## 5. IPv6、NAT 和安全组要额外核对

**IPv6**：服务器有 IPv6 不等于客户端网络能访问 IPv6。确认客户端网络有 IPv6、域名的 AAAA 记录正确、服务监听及防火墙覆盖 IPv6。只输入字面 IPv6 地址时不加 URL 方括号，分享链接会正确生成方括号。域名默认监听 IPv4；双栈需要按 README 的 `--listen ::` 说明配置并核对系统行为。仅有 IPv4 的 VPS 可以使用 IPv4，诊断提示 IPv6 不可用不一定是故障。

**NAT VPS**：公网地址和外部端口由服务商映射到你的机器。自动探测通常只知道出站公网地址，不能证明该地址及端口能接受客户端入站。当前节点只保存一项端口，未提供独立“公网映射端口”字段；建议使用内外一致的端口映射。如果外部端口与本机监听端口不同，导出内容需要在客户端核对并改为外部端口，服务器仍使用本机实际监听端口。确认 TCP/UDP 映射分别覆盖所选协议，程序不会替你设置上游 NAT。

**云安全组与本机防火墙**：前者在服务商控制台，后者在 VPS 内。两层都要允许表格中的协议/端口。Hysteria2 的 TCP 80 签发条件与 UDP 节点端口分开检查。不要为测试节点清空所有规则或修改 SSH；可以先运行 `sudo qingnode firewall status` 查看本机检测和所需端口，再按自己使用的防火墙方案处理。

## 6. 进行一次自己的真实连接测试

1. 在客户端中选中刚导入的节点，启用客户端所需的代理入口。
2. 测试实际 HTTPS 访问，并确认流量确实经过该节点；按客户端功能检查 UDP 的实际传输。没有测过的项目保持“未验证”。
3. 服务器上查看 `sudo qingnode overview` 和 `sudo qingnode status`。服务运行、监听存在、配置检查通过只证明对应的本机事实。
4. 连不上时先看 [FAQ 的连接故障流程](FAQ.md#服务运行中但客户端连接失败)，保留具体错误，不要重新生成身份尝试碰运气。

公网历史记录由管理员登记。若已经实际测试，可以使用菜单 `5 网络与诊断 → 6 公网验证说明/登记`，将通过、失败、未验证分别记录；它不会替你自动证实网络。修改配置或时间过去以后要重新检查，历史成功不代表持续在线。

## 7. 后续修改、备份与凭据保管

修改地址、端口、SNI、指纹或认证参数后，重新导出受影响节点并更新客户端。改端口还要同步云安全组、NAT 映射和手动防火墙。普通编辑保留 UUID、密码和 REALITY 密钥；明确轮换身份时，旧客户端可能失效。轮换单个凭据影响对应设备；REALITY 密钥/short ID 或 SS2022 服务密钥轮换会影响该节点更大的客户端范围，以执行前提示为准。

在配置正常、没有待恢复事务时，重大调整前运行 `sudo qingnode backup`，设置至少 12 字节的强口令，保存实际输出的备份路径，并把加密备份及口令分别保存在 VPS 之外。若安装或配置变更已经中断，先运行 `sudo qingnode doctor` 查明情况并保留当前目录、事务记录和日志；不要先用 `backup` 保存故障现场，它仍可能自动恢复事务、改变配置或启停服务。备份不是整机镜像，不包含 ACME 账户/证书缓存、核心二进制和全机防火墙；恢复流程及范围见 [FAQ](FAQ.md#恢复中断事务回退配置还是恢复备份)。

URI、二维码、客户端文件、`--show-secrets` 输出、私钥及明文卸载快照都包含敏感内容。默认的 `list`、`info` 用于查看概要；反馈故障时不要附完整 URI、二维码、私钥、密码或未加密状态文件。脱敏日志也应在发送前自己检查。
