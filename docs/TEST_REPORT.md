## 边界与下一步

该包是开发验收包，尚不能称为已通过生产 VPS 验收。配置/卸载事务有持久记录，但 Shell 安装器遭遇 SIGKILL、断电、持久文件系统错误或不可用的 systemd/UFW 时，可能需要人工重试。

UFW 自动管理只处理已启用 UFW 中可确定归属的规则；其他后端和复杂混合策略人工处理。ACME 缓存、全机防火墙、BBR 和核心二进制不在配置快照中。严重损坏的节点数据库需先找回有效历史数据。旧版本无归属记录的遗留账户不会被自动接管。

后续优先运行真实 VPS 验收与公网客户端测试，再扩展 TUIC、完整英文、ACME 缓存迁移及在线订阅。附带源码中的 scripts/acceptance-vps.sh 仅应显式用于可重建空白 VPS；它不会改变防火墙或 BBR。

## 0.2.2：真实系统字段导致的在线安装失败

用户在 Ubuntu 24.04.4 上报告第 3 步“仓库名或正式版本号无效”。根因是安装器在当前 Shell 中加载 `/etc/os-release`，其人类可读的 `VERSION` 覆盖了管理器版本 `v0.2.1`。原模拟文件只包含 `ID` 和 `VERSION_ID`，因此遗漏了该问题；先前通过的模拟测试不能证明在线入口在真实系统上可安装。

已先补上含 `VERSION` / `PRETTY_NAME` 的夹具，在旧代码上实际复现同一错误；直接读取开发宿主的真实文件也确认版本由 `v0.2.1` 变为 `24.04.3 LTS (Noble Numbat)`。修复后在子进程中读取系统信息，只传回专用的系统 ID / 版本字段，默认和显式指定的发行 tag 均保持。仓库与版本错误分别报告，并拒绝 `.` / `..` 仓库路径段。
