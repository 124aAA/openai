## 当前架构与功能

Bash 引导安装，Go CLI 负责统一 State、协议配置与系统管理，官方 sing-box 1.14.0 负责流量，systemd 使用专用低权限账户。没有 Docker/Web 面板。REALITY/Vision、Hysteria2、多节点、多用户、URI/二维码/Mihomo/sing-box 导出、配置代、回退、状态加密备份已经实现。

## 问题和优先级

| 发现 | 影响 | 处理 |
| --- | --- | --- |
| 安装回滚只覆盖二进制/服务文件，前置目录和账户可能残留 | 重试可能被半安装状态阻挡 | P0 记录安装前所有权，早注册清理；账户失败后保留有标记的可重试状态 |
| 启动/重启内隐含 systemctl enable | 用户明确禁用自启后被重新启用 | P0 自启与运行分离 |
| 端口所有权只看历史 State，监听只看全机端口 | 无关进程可能被误认为节点就绪；停机后端口被占不被预检发现 | P0 对照 MainPID 与 socket inode |
| 状态诊断会先自动恢复事务；状态损坏时诊断直接退出 | 故障时缺乏可操作输出，读操作可能重启服务 | P0 只读诊断、分级检查与建议 |
| PEM 时间有效性混在整份 State 校验中 | 一个过期证书可阻止备份和其他节点操作 | P0 结构校验与运行就绪检查分开 |
| 卸载缺少事务恢复；默认仅删管理器和 unit | 中断后状态不清晰，无法选择只卸载核心 | P0 事务卸载及保留配置模式 |
| init 幂等、编辑端口不改 UUID/密钥已正确实现 | 稳定身份可以继续使用 | 保留并扩大回归 |
| 候选配置错误不激活，历史代和失败回退已实现 | 可靠性基础良好，但失败候选会累积 | 保留，补清理与故障路径测试 |
| 菜单缺少大量已有 CLI 功能，状态只有 active | 新手无法独立完成长期维护 | P1 分级菜单、完整信息、CLI 别名 |
| 无随机端口、独立 short ID、fingerprint、时间戳 | 参数管理不方便 | P1 增量字段、兼容旧状态 |
| 备份只有 State，无 systemd/实际生成配置 | 恢复材料不完整 | P1 版本化加密快照、恢复前备份，兼容旧备份 |
| 无 BBR；防火墙仅 UFW 只读 | 不是隐藏的优化功能，也不存在清空规则 | P1 增加独立、可回退的 BBR；只在能确认规则归属时自动管理 |
| 核心更新已有版本锁/摘要与旧核心保留，无最新版本查询/自身更新 | 更新步骤不完整 | P1 分离核心与管理器更新，失败保留旧版本 |
| main.go 953 行；协议分支在校验/生成/导出重复 | 新协议易落入 Hysteria2 默认分支 | 有收益地拆出 UI/诊断/系统管理，P2 集中协议适配 |
| 安装器只接受 Debian12/13、Ubuntu24.04 | 缺少用户指定系统 | 增加 22.04/26.04 识别、明确未实测提示与验收入口 |

## 安全与测试边界

已有参数使用 Go 序列化及参数数组；未发现 eval、iptables -F、SSH 配置改写或第三方内核安装。仍须完善错误日志脱敏、安装器临时文件/回滚、失败下载与命令返回值验证。不能把 mock、配置解析和交叉编译写成真实 VPS 验收。

当前环境不是 systemd 宿主，上一轮实际 sing-box 启动被路由订阅权限拒绝。真实 Debian/Ubuntu 安装、ACME、Android、ARM64 和公网连接均未验证，本轮将重跑能够执行的测试并提供其余验收入口。

## 实施中的复审修正

- 发现状态未变但派生 server.json 损坏时，原 no-op 会阻止修复；改为同时比对派生文件，重建时保持身份和时间戳。
- 发现升级到不同版本可能提前复用旧归档摘要；摘要现在在目标版本确定后匹配。
- 发现卸载中断时 ensure 可能创建空 cores，挡住旧目录归位；恢复先处理旧目录，并增加 Store 层回归。
- 发现完全卸载保留账户与重新安装拒绝同名账户之间存在冲突；增加权限 600 的精确账户归属记录，不放宽外部账户保护。
- 卸载快照统一为 v2，增加明确的明文快照恢复入口；损坏的派生 JSON 也能保留为备份证据。
- 安装器故障测试先修正模拟环境的临时目录及原子状态写入，再验证真正的故障点被触发，未将提前失败误算为回滚通过。
